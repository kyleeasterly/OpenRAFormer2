Across both players, 114 of 258 attack/attack-move submissions involved one unit.

Both refinery placements happened around 54 seconds. The original placement
question supplied distance from the footprint's top-left to resource centroids,
without docking routes or patch size in its choices. Alpha's nearest reported
fragment contained just two resource cells. Neither player added harvesting
capacity. Beta recruited 16 unarmed engineers without ever issuing capture, and
bought eight power plants; at 20 minutes it had 1,106 power for 435 demand. Alpha
later remained underpowered after losing construction capacity. These observations
motivated specialized refinery, investment, combat, and maintenance questions.

## Candidate and controls

The [v2 architecture](../JEV.md#v2-spatial-economy-and-combat-questions) adds
player-visible docking routes and patch quantities, investment context, physical
and role-based grouping, common operations, separate maneuver/target questions,
and repair/sale choices. Every selected strategy and directive still comes from
native Jev. Candidate generation, grouping, budgeting, and validation are code.

`JevPolicy.cs` is preserved unchanged. V1 retains the original observation shape,
five-second command hold, and all other original policy defaults. V2's two-second
hold is an intentional part of the candidate. This tests complete harnesses,
not the isolated effect of any one change.

Both sides use GDI on Scorched Earth, one-second state exports and request cadence,
the same native provider/model route, and the same initial resources. The first
comparison places v2 at spawn 1 and v1 at spawn 8; the second swaps them. Matches
run sequentially to avoid competing engine render loads. Victory and duration
come from the engine's final result. No game-clock cap or artificial victory rule
is used. Two matches are a practical demonstration, not a win-rate estimate.

## Results

The paired comparison is in progress. Results will be filled from the recorded
engine outcomes and analysis artifacts before this experiment is reported complete.

An initial launch, `20260917-071045-jev-v2-v1`, was stopped after an export exception
left observations frozen at second 2. A mod rule spells the refinery's free actor
`HARV`, while the rules dictionary uses lowercase names. The lookup now normalizes
the name. This launch is a failed integration attempt and is excluded from gameplay
results; its logs are retained.

The next integration attempt, `20260917-071854-jev-v2-v1`, revealed empty docking
routes for every site. The refinery's `+` apron cells are occupied but permit
transit; excluding all occupied cells incorrectly blocked the dock itself. Routing
now excludes only solid footprint cells. Engine-level regression tests exercise
the real footprint semantics and disconnected terrain. This run was stopped at
3:14 and is also excluded from the paired gameplay results.

Run `20260917-072345-jev-v2-v1` exposed a third integration failure at decision
229: TypeSafe returned HTTP 400 with `max_tokens_exceeded`. Earlier requests had
reached 32,659 reported input tokens; the next refinery choice exceeded the
provider's input limit. V2 stopped while v1 kept playing, so this run was stopped
and does not count as a completed gameplay comparison. The request had repeated
patch quantities and item rules across its alternatives. The revised candidate
stores those facts once, limits local targets, and samples large placement/target
lists to a 48,000-character request budget. Explicit native size errors reduce
that budget on the next fresh observation instead of immediately ending the loop.
Re-evaluating the failed observation succeeds at 18,580 input tokens; a probe using
the largest recorded observation from the original duel succeeds at 20,407 tokens.

Development trial `20260917-073405-jev-v2-v1` was stopped without a winner. It
showed excessive preparation: seven harvesters, a peak $6,300 army, tightly grouped
units, but zero distant combat advances. Near second 500, the growing collection
of questions also exceeded the whole-turn character guard. The final candidate
adds an explicit coordinated launch/scout decision, discourages harvesting
investment when cash accumulates or income already covers spending, and splits
large turns into bounded native batches with the identical observation. The
opening-state probe now selects a detached scout. This development trial is
reported as unsuccessful, not counted as a win or omitted from the experiment.

Development trial `20260917-075109-jev-v2-v1` revealed that local advance choices
could bypass a campaign hold, producing more small departures. It was stopped
without a winner to make campaign commitment authoritative for preparing groups.
The observer also identified groups continuing to attack structures while newly
produced infantry and turrets entered combat. The trace confirms a concrete-barrier
target as a new tank and minigunner appeared. The final candidate adds a native
threat-interrupt question with priority over ordinary orders and their hold timer.

## Reproduction and measurements

Specs: `orf/specs/jev-v2-v1.yaml` and `orf/specs/jev-v2-v1-reverse.yaml`.

```bash
source ~/.orf-secrets
make
dotnet build orf/Orf.csproj -c Release
dotnet orf/bin/Release/net10.0/orf.dll run --spec orf/specs/jev-v2-v1.yaml
dotnet orf/bin/Release/net10.0/orf.dll run --spec orf/specs/jev-v2-v1-reverse.yaml
python3 orf/analyze_jev.py runs/<first-run> runs/<reverse-run>
```

The analysis script uses recorded turns without new model calls. It writes
`analysis.json` beside each run. Purchase and command counts are submissions;
engine rejections are reported separately. Peak army value sums the rules' purchase
costs of observed armed units. It does not estimate matchup strength. Group span
is maximum pairwise cell distance within each observed non-singleton group.

A distant advance is an attack-move by armed units at least 25 cells from their
current centroid, with a destination within 20 cells of a known enemy start or
remembered enemy building. Command sizes count armed members; unarmed engineers
are excluded from this combat metric. It is an isolated single-unit advance when
the command has one armed member and at most one armed friendly is within 10
cells of its origin. This
metric is imperfect: it includes some scouts and excludes short-range trickling.
Medians pool observations, not independent battles. Low-power counts measure
recorded observations, not inferred wall-clock duration. API latency is approximated
from request/response file times; actual provider model IDs and failures are retained.

The local run artifacts include full player observations, native request/response
payloads, selected orders, execution decisions, engine acknowledgements, and replay.
They are gitignored because of size. The reproducible specifications, analyzer,
and this report belong in version control.

## Validation

`make check` passes. The Orf suite passes 34 tests, including v2 reinforcement
separation, removal of legacy questions after casualties, specialist grouping,
conditional local targets, refinery choice metadata, repair-toggle revalidation,
rejection of expired tactical decisions, candidate sampling with matching actions,
recognition of the native size error, native batch consistency/aggregation,
campaign order precedence, scout detachment, authoritative campaign holds, and
new infantry/turret interrupts during an active command hold. Two engine-level spatial tests pass,
covering the refinery apron and blocked/disconnected routes. The restarted live game verifies
that the real mod's refinery metadata exports successfully; unit fixtures alone
did not catch the actor-name casing error above.
